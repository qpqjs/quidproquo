# Issue #64: aiModelMap: map Sonnet 5.5 to its au. Bedrock inference profile

**Verdict:** enhancement
**Status:** ready
**Branch:** `issue-64`

## Summary

`AiModel.ClaudeSonnet55` is the only current Claude model in `bedrockModelMap` that lists just a `global.` inference profile, because no `au.` profile existed when #54 added it. Bedrock now lists `au.anthropic.claude-sonnet-5-5` in `ap-southeast-2`, so the entry should point at it the same way `ClaudeOpus55` and the rest do, and the docs that call Sonnet 5.5 "Global only" need to stop saying so.

## Affected packages

- `@qpqjs/actionprocessor-aws`: owns `bedrockModelMap` in `src/getActionProcessor/core/ai/utils/aiModelMap.ts`, which `resolveBedrockModel` (same folder) turns into the profile id `prepareAiPromptCall` sends, and which `getAiGetModelRegionsActionProcessor` walks to answer `askAiGetModelRegions`. Its tests in `aiModelMap.test.ts` assert the current Global-only shape by name.
- `quidproquojs.com`: `docusaurus/docs/actions/core/ai/ask-ai-prompt.md` and `ask-ai-get-model-regions.md` list Sonnet 5.5 as Global in the `AiModel` table and in prose.

Nothing in `@qpqjs/core` changes: the `AiModel` member, `AiDataRegion` and `AiModelRegionMap` already exist. No IAM change either: `QpqCoreAiConstruct` grants `bedrock:InvokeModel` on `arn:aws:bedrock:${region}:${accountId}:inference-profile/*`, which covers an `au.` profile exactly as it covers the `global.` one. `bedrockOneHourCacheModels` is keyed by model, not profile, so it stays as is.

## Approach

1. **Swap the map entry** in `packages/actionprocessor-aws/src/getActionProcessor/core/ai/utils/aiModelMap.ts` line 23. Replace

   ```ts
   [AiModel.ClaudeSonnet55]: { [AiDataRegion.Global]: 'global.anthropic.claude-sonnet-5-5' },
   ```

   with

   ```ts
   [AiModel.ClaudeSonnet55]: { [AiDataRegion.Australia]: 'au.anthropic.claude-sonnet-5-5' },
   ```

   Keep it in its current position (enum order). The id is the `inferenceProfileId` the reporter read from `aws bedrock list-inference-profiles --region ap-southeast-2` on 5 Nov 2026 and exercised with a Converse call, so it has no `-v1` style suffix. If the implementer has AWS access, re-run that command and copy the id verbatim before committing; a wrong id only fails at request time.

   Do not keep `Global` as a second entry. `bedrockDataRegionPreference` is fixed at Australia then Global, so the `global.` id would never be sent, and `askAiGetModelRegions` would report Sonnet 5.5 as offered in both regions, which a model picker could show as "may leave Australia" for a model that never does. Every other model with an `au.` profile lists Australia alone; Sonnet 5.5 should match. The `BedrockModelRegions` type already allows several regions, so adding Global back is a one-line change once the preference order is configurable (the comment in `bedrockDataRegionPreference.ts` says that is coming).

2. **Update the map tests** in `packages/actionprocessor-aws/src/getActionProcessor/core/ai/utils/aiModelMap.test.ts`:
   - In `offers the Global-only models through their global. profile and nowhere else` (line 33), drop the `ClaudeSonnet55` expectation and assert `ClaudeFable5` alongside `ClaudeFable51`, so the test still names every Global-only model.
   - Add a `ClaudeSonnet55` expectation to `maps ClaudeOpus55 to its au. inference profile and nowhere else` (line 38), or a sibling case, asserting `toEqual({ [AiDataRegion.Australia]: 'au.anthropic.claude-sonnet-5-5' })`. Rename the case to cover both models.
   - The `it.each` cases (every model offered somewhere, every id under the region its prefix names) and `covers every AiModel enum member` need no change and will pass with the new entry, since the id starts with `au.` and sits under `Australia`.
   - `getAiGetModelRegionsActionProcessor.test.ts` and `resolveBedrockModel.test.ts` do not mention Sonnet 5.5 (the resolver test mocks the map) and need no change.

   Run with `npm run test -w @qpqjs/actionprocessor-aws`.

3. **Update the docs** in `quidproquojs.com/docusaurus/docs/actions/core/ai/`:
   - `ask-ai-prompt.md` line 81: change the `ClaudeSonnet55` row's data region from `Global` to `Australia`.
   - `ask-ai-prompt.md` line 85: the last sentence becomes "Fable 5 and Fable 5.1 have no `au.` profile, so they are Global only."
   - `ask-ai-get-model-regions.md` line 11: "Sonnet 5.5, Fable 5 and Fable 5.1 have only a `global.` profile" becomes "Fable 5 and Fable 5.1 have only a `global.` profile", and "so those three run through their Global profile" becomes "so those two".
   - `ask-ai-get-model-regions.md` line 40: "Sonnet 5.5, Fable 5 and Fable 5.1 are Global only." becomes "Fable 5 and Fable 5.1 are Global only."

4. **Changelog.** `CHANGELOG.md` only carries released versions and the `/changes` skill assembles the next entry at release time, so nothing is edited now. The line for that entry: `actionprocessor-aws: \`AiModel.ClaudeSonnet55\` runs through its new \`au.\` Bedrock inference profile instead of \`global.\`, so it stays in Australia like the other current models`. Not a breaking change (no API or type changes), so nothing goes under `## vNext` in `breaking-changes.md`. It is a behaviour change worth the changelog line: an app already calling Sonnet 5.5 will see a different `modelId` in its traces and will now be subject to the `au.` profile's quotas rather than the global ones.

5. **Lint and build** with `npm run lint -w @qpqjs/actionprocessor-aws` and `npm run build -w @qpqjs/actionprocessor-aws`. The vitest config aliases `@qpqjs/core` to its `src`, so the tests in step 2 run without a build.

## Open questions

None. The reporter has already verified the profile id against the CLI and with a live Converse call, and left the keep-Global decision to the maintainers, which step 1 settles.
