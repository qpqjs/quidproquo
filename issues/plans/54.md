# Issue #54: AiModel: add current Claude models mapped to their au. Bedrock inference profiles

**Verdict:** enhancement
**Status:** ready
**Branch:** `issue-54`

## Summary

`AiModel` stops at the 4.6 generation, so an app that lets a user pick a model cannot offer anything newer without a framework release. Add six enum members for the current Claude models and map each to its `au.` Bedrock cross-region inference profile in `bedrockModelMap`, so requests keep running in Australia like the existing entries. Sonnet 5.5 is deliberately left out because it has no `au.` profile yet.

## Affected packages

- `quidproquo-core`: owns the `AiModel` enum in `src/actions/ai/AiModel.ts`.
- `quidproquo-actionprocessor-awslambda`: owns `bedrockModelMap` in `src/getActionProcessor/core/ai/aiModelMap.ts`, which `prepareAiPromptCall` uses to turn an `AiModel` into a Bedrock model id. The map is typed `Record<AiModel, string>`, so adding an enum member without a map entry fails the build.
- `quidproquojs.com`: the `AiModel` member table in `docusaurus/docs/actions/core/ai/ask-ai-prompt.md` lists every member and needs the new rows.

Nothing else changes. `QpqCoreAiConstruct.authorizeActionsForRole` grants `bedrock:InvokeModel` and `bedrock:InvokeModelWithResponseStream` on `*`, so no IAM change is needed for new profiles. The dev server and node processors have no AI action processor, so there is no second map to keep in sync.

## Approach

1. **Add the enum members** in `quidproquo-core/src/actions/ai/AiModel.ts`, appended after `ClaudeOpus46` and named the same way as the existing members (family then version digits, no separator):

   | Member | Value |
   | --- | --- |
   | `ClaudeOpus47` | `claude-opus-4-7` |
   | `ClaudeOpus48` | `claude-opus-4-8` |
   | `ClaudeSonnet5` | `claude-sonnet-5` |
   | `ClaudeOpus5` | `claude-opus-5` |
   | `ClaudeHaiku55` | `claude-haiku-5-5` |
   | `ClaudeOpus55` | `claude-opus-5-5` |

   The string values are the ones the reporter asked for and match the shape of `ClaudeSonnet46 = 'claude-sonnet-4-6'`. Keep this order (by generation) since `Object.values(AiModel)` is what a model picker iterates.

2. **Map each member to its inference profile** in `quidproquo-actionprocessor-awslambda/src/getActionProcessor/core/ai/aiModelMap.ts`, in the same order:

   | Member | Bedrock inference profile |
   | --- | --- |
   | `ClaudeOpus47` | `au.anthropic.claude-opus-4-7` |
   | `ClaudeOpus48` | `au.anthropic.claude-opus-4-8` |
   | `ClaudeSonnet5` | `au.anthropic.claude-sonnet-5` |
   | `ClaudeOpus5` | `au.anthropic.claude-opus-5` |
   | `ClaudeHaiku55` | `au.anthropic.claude-haiku-5-5` |
   | `ClaudeOpus55` | `au.anthropic.claude-opus-5-5` |

   Before committing, run the command below and copy the `inferenceProfileId` strings verbatim. The existing 4.6 entries show the suffix is not predictable (`au.anthropic.claude-sonnet-4-6` has none, `au.anthropic.claude-opus-4-6-v1` has `-v1`), and a wrong id only fails at request time with a Bedrock validation error, not at build.

   ```
   aws bedrock list-inference-profiles --region ap-southeast-2 \
     --query "inferenceProfileSummaries[?starts_with(inferenceProfileId, 'au.anthropic.claude')].inferenceProfileId"
   ```

   Do not add Sonnet 5.5. Mapping it to a `global.` profile would route requests outside Australia, which is the opposite of what the map is for. It gets its own entry once an `au.` profile exists.

3. **Extend the map test** in `quidproquo-actionprocessor-awslambda/src/getActionProcessor/core/ai/aiModelMap.test.ts`. The existing `it.each(Object.values(AiModel))` and "covers every AiModel enum member" cases pick up the new members with no change. Add one explicit assertion alongside the `ClaudeHaiku35` one, for example that `ClaudeOpus55` maps to `au.anthropic.claude-opus-5-5`, so a typo in the newest id is caught by name. Run with `npm run test -w quidproquo-actionprocessor-awslambda`.

4. **Update the docs table** in `quidproquojs.com/docusaurus/docs/actions/core/ai/ask-ai-prompt.md` under the `AiModel` heading (around line 61). Add six rows in the same order as the enum: `ClaudeOpus47` Claude Opus 4.7, `ClaudeOpus48` Claude Opus 4.8, `ClaudeSonnet5` Claude Sonnet 5, `ClaudeOpus5` Claude Opus 5, `ClaudeHaiku55` Claude Haiku 5.5, `ClaudeOpus55` Claude Opus 5.5.

5. **Leave the defaults alone.** `defineEventDocAi` (`quidproquo-features/src/eventDocAi/config/defineEventDocAi.ts` line 55), `EventDocAiOptions`, `defineAdminSettings` line 278 and the docs examples all default to `AiModel.ClaudeSonnet46`. The issue asks for new options, not a new default, and moving the default changes cost and behaviour for every app that does not set `model`. If a maintainer wants the default bumped that is a separate change.

6. **Changelog.** For the release that carries this, add a line under the next version in `CHANGELOG.md`: `core/actionprocessor-awslambda: \`AiModel\` gains \`ClaudeOpus47\`, \`ClaudeOpus48\`, \`ClaudeSonnet5\`, \`ClaudeOpus5\`, \`ClaudeHaiku55\` and \`ClaudeOpus55\`, each mapped to its \`au.\` Bedrock inference profile`. Not a breaking change: existing members and ids are untouched.

7. **Lint and build** with `npm run lint -w quidproquo-core -w quidproquo-actionprocessor-awslambda` and `npm run build -w quidproquo-core -w quidproquo-actionprocessor-awslambda`. The build of the lambda package is the check that every new member has a map entry.
