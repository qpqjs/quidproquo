# Issue #54: AiModel: add current Claude models mapped to their au. Bedrock inference profiles

**Verdict:** enhancement
**Status:** in-progress
**Branch:** `issue-54`

## Summary

`AiModel` stopped at the 4.6 generation, so an app that lets a user pick a model could not offer anything newer without a framework release. Add enum members for the current Claude models and map each to its `au.` Bedrock cross-region inference profile in `bedrockModelMap`, so requests keep running in Australia like the existing entries.

Most of this shipped in 0.1.30. Opus 4.7, Opus 4.8, Sonnet 5, Opus 5 and Opus 5.5 are in the enum and mapped to their `au.` profiles. Sonnet 5.5, Fable 5 and Fable 5.1 went in too, as Global-only entries, and the map became per-region with `askAiGetModelRegions` so a picker can hide models that have no Australian profile. The one item from the issue still missing is Haiku 5.5.

## Affected packages

- `quidproquo-core`: owns the `AiModel` enum in `src/actions/ai/AiModel.ts`.
- `quidproquo-actionprocessor-awslambda`: owns `bedrockModelMap` in `src/getActionProcessor/core/ai/aiModelMap.ts`, typed `Record<AiModel, BedrockModelRegions>`, so adding an enum member without a map entry fails the build. `bedrockOneHourCacheModels` and `bedrockBudgetThinkingModels` in the same folder decide the cache ttl and thinking shape per model and are opt-in sets, so a new member only needs adding where it belongs.
- `quidproquojs.com`: the `AiModel` member table in `docusaurus/docs/actions/core/ai/ask-ai-prompt.md` lists every member and its data regions.

No IAM change: `QpqCoreAiConstruct.authorizeActionsForRole` grants Bedrock invoke on `*`.

## Approach

Remaining work, for Haiku 5.5 only. The other five models from the issue are already on `main`.

1. **Add the enum member** `ClaudeHaiku55 = 'claude-haiku-5-5'` in `quidproquo-core/src/actions/ai/AiModel.ts`, between `ClaudeOpus5` and `ClaudeOpus55` so `Object.values(AiModel)` stays in generation order.

2. **Map it** in `quidproquo-actionprocessor-awslambda/src/getActionProcessor/core/ai/aiModelMap.ts` as `{ [AiDataRegion.Australia]: 'au.anthropic.claude-haiku-5-5' }`, in the same position. Confirm the id against the CLI first; the 4.6 pair shows the suffix is not predictable (`au.anthropic.claude-sonnet-4-6` has none, `au.anthropic.claude-opus-4-6-v1` has `-v1`), and a wrong id only fails at request time.

   ```
   aws bedrock list-inference-profiles --region ap-southeast-2 \
     --query "inferenceProfileSummaries[?starts_with(inferenceProfileId, 'au.anthropic.claude-haiku')].inferenceProfileId"
   ```

3. **Add it to `bedrockOneHourCacheModels`** if the Bedrock prompt caching table lists one-hour ttl for Haiku 5.5, as it does for the rest of the 5.x line. Leave it out of `bedrockBudgetThinkingModels`: the 5.x models run adaptive thinking.

4. **Extend the map test** in `aiModelMap.test.ts` with an assertion that `ClaudeHaiku55` maps to `{ Australia: 'au.anthropic.claude-haiku-5-5' }` and nothing else, next to the `ClaudeOpus55` one. The enum-coverage cases pick the member up on their own. Run with `npm run test -w quidproquo-actionprocessor-awslambda`.

5. **Docs table.** Add a row `ClaudeHaiku55` / Claude Haiku 5.5 / Australia to `quidproquojs.com/docusaurus/docs/actions/core/ai/ask-ai-prompt.md` in enum order.

6. **Leave the defaults alone.** `defineEventDocAi` and the admin settings default to `AiModel.ClaudeSonnet46`; this issue adds options, not a new default.

7. **Changelog.** Under the next version in `CHANGELOG.md`: `core/actionprocessor-awslambda: \`AiModel\` gains Claude Haiku 5.5, mapped to its \`au.\` Bedrock inference profile`.

8. **Lint and build** with `npm run lint -w quidproquo-core -w quidproquo-actionprocessor-awslambda` and `npm run build -w quidproquo-core -w quidproquo-actionprocessor-awslambda`.
